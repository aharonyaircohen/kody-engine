# Operating Kody

How agents and people drive Kody from GitHub. For the engine's internals and the full structural model, see [AGENTS.md](AGENTS.md) and [docs/jobs-model.md](docs/jobs-model.md).

---

## 1. The core idea

Kody is a **command bot**, not a chat partner. It acts only on a comment that literally contains `@kody`. No `@kody`, no action — it has no inbox and reads nothing else.

When you comment, the engine turns your request into a **job** (one run) and executes it.

---

## 2. How to trigger it

**Comment on an issue or PR:**

```
@kody <command> [free text]
```

- The first word after `@kody` is the command. With no word, it falls back to the default: **`run`** on an issue. (On a PR there is no default unless the repo configures one.)
- Free text after the command is passed to the agent (e.g. `@kody run also handle the empty-list case`).

**Manual:** GitHub Actions → `workflow_dispatch` with an issue number. No comment needed.

---

## 3. What commands exist

**Engine-shipped (always available):**

| Command(s) | Runs on | Does |
|---|---|---|
| `run` *(default)* | an issue | implement the issue → open a PR |
| `resolve`, `sync`, `revert`, `merge` | a PR | PR-lifecycle operations |
| `preview-build` | a PR | build a per-PR preview |
| `release` | an issue | run the engine's own release flow |

**Consumer-defined:** a repo can add its own commands under `.kody/executables/<name>/` (e.g. `fix`, `bug`, `feature`, `review`). These are **not** part of the engine — they exist only in repos that define them. To see what a given repo accepts, look in its `.kody/executables/`.

Scheduled work (recurring duties) is **not** comment-driven — it runs on a cron via the schedulers.

---

## 4. How to re-trigger

Post a **new** `@kody …` comment. **Editing** an existing comment does nothing — the workflow only listens for newly *created* comments. (Or re-run via `workflow_dispatch`.)

---

## 5. What NOT to do

- ❌ **Don't leave a plain comment and expect Kody to read it.** No `@kody`, no run — the workflow never even starts.
- ❌ **Don't expect a bot's or agent's prose to wake Kody.** Even with `@kody`, a bot-authored comment is honored only when it's an explicit `@kody <command>`; ordinary bot chatter is dropped on purpose (loop protection).
- ❌ **Don't write `@kodyade[bot]`, `@kody-engine`, or `@kody-foo`.** Only a standalone `@kody` is recognized.
- ❌ **Don't invent commands.** If a command isn't engine-shipped (above) or defined in the repo's `.kody/executables/`, it won't run.
- ❌ **Don't rely on a comment from a non-allowlisted user** when the repo sets `access.allowedAssociations`.
